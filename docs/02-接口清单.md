# 美食社区 · 接口清单（REST API）

## 0. 全局约定

- **统一前缀**：`/api`；管理端前缀 `/api/admin/*`
- **返回结构**：`Result<T>` = `{ code, msg, data }`（code=200 成功；401 未登录/凭证失效；403 无权限；500 业务/系统错误）
- **分页结构**：`Page<T>` = `{ records, total, current, size }`（PageHelper）
- **鉴权**：JWT（java-jwt），请求头 `Authorization: Bearer <token>`

**拦截规则（两个拦截器，白名单式）**

| 请求 | 是否需登录 |
|---|---|
| `POST /api/auth/login`、`POST /api/auth/register`、所有非 admin 的 GET | ❌ 公开（游客可浏览） |
| 其余非 admin 的 POST/PUT/DELETE | ✅ 需登录（JWT 校验） |
| 所有 `/api/admin/*` | ✅ 需登录 **且 role=管理员**（无 token 401，非管理员 403） |
| `WS /api/ws/chat` | ✅ 握手时 query 携带 token 校验 |

- **图片上传**：`POST /api/upload`（登录即可），multipart `file` 字段，白名单 jpg/png/webp ≤5MB，返回 `data = { url: "/uploads/xxx.jpg" }`

## 1. 账号模块（用户端）

| Method | Path | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/auth/register` | 公开 | 注册（username/password/nickname），默认 role=0 |
| POST | `/api/auth/login` | 公开 | 登录，返回 `{token, user:{id,username,nickname,avatar,role,isExpert}}`，前端按 role 分流 |
| GET | `/api/user/me` | 登录 | 当前用户完整资料（含 intro、createTime） |
| PUT | `/api/user/me` | 登录 | 修改昵称/头像/简介 |
| PUT | `/api/user/me/password` | 登录 | 改密（oldPassword + newPassword，需校验旧密码） |

## 2. 首页（用户端，全部公开 GET）

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/banner/list` | 轮播图列表（JOIN 菜谱标题/封面，仅关联已通过菜谱，按 sort 排序） |
| GET | `/api/recipe/hot` | 热门菜谱（status=1，views 降序，默认 8 条） |
| GET | `/api/store-visit/hot` | 热门探店（status=1，views 降序，默认 8 条） |
| GET | `/api/notice/latest` | 最新公告（默认 1 条） |

## 3. 菜谱模块

| Method | Path | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/category/list` | 公开 | 全部分类（用户端按分类浏览下拉用） |
| GET | `/api/recipe` | 公开 | 菜谱分页列表，参数：`page, size, categoryId?, keyword?(标题模糊), 仅返回 status=1` |
| GET | `/api/recipe/{id}` | 公开 | 菜谱详情：主表 + 食材清单 + 步骤 + 作者信息；**访问即 views+1**；登录态额外返回 `isLiked/isFavorited` |
| POST | `/api/recipe/{id}/like` | 登录 | 点赞（写 recipe_like + likes_count+1，幂等） |
| DELETE | `/api/recipe/{id}/like` | 登录 | 取消点赞 |
| POST | `/api/recipe/{id}/favorite` | 登录 | 收藏（幂等） |
| DELETE | `/api/recipe/{id}/favorite` | 登录 | 取消收藏 |

## 4. 评论模块（楼中楼）

| Method | Path | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/recipe/{id}/comments` | 公开 | 评论分页（按根评论分页，每条带其子评论，最多两层展示但存储无限层） |
| POST | `/api/recipe/{id}/comment` | 登录 | 发评论；body：`content, parentId?, rootId?, replyUserId?`（缺省=根评论） |
| DELETE | `/api/comment/{id}` | 登录 | 删除自己的评论，**服务层递归删除其所有子孙** |

## 5. 探店 / 达人 / 预约模块

| Method | Path | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/store-visit` | 公开 | 探店分页（仅 status=1），点击列表项弹详情（内嵌 views+1 接口） |
| GET | `/api/store-visit/{id}` | 公开 | 探店详情 + views 自增 |
| GET | `/api/expert/list` | 公开 | 探店达人榜：`is_expert=1`，带 heat=SUM(通过探店 views)*2，降序，分页 |
| GET | `/api/user/{id}/profile` | 公开 | 作者/达人主页信息（nickname/avatar/intro/isExpert + 统计：菜谱数/探店数） |
| GET | `/api/user/{id}/recipes` | 公开 | 该作者 status=1 的菜谱分页 |
| GET | `/api/user/{id}/store-visits` | 公开 | 该作者 status=1 的探店分页 |
| POST | `/api/reservation` | 登录 | 发起预约，body：`expertId, storeName, storeIntro?, storeAddress?, phone?, remark?`（后端校验 expertId 是达人） |
| GET | `/api/my/reservations` | 登录 | 我的预约分页：`direction=initiated`（我发起的）或 `received`（我接收的） |
| POST | `/api/my/reservations/{id}/agree` | 达人 | 同意（仅 expert_id=me 且 status=0 可操作） |
| POST | `/api/my/reservations/{id}/reject` | 达人 | 拒绝，body：`reason` 必填 |

## 6. AI 美食专家（登录，SSE 流式）

| Method | Path | 说明 |
|---|---|---|
| POST | `/api/ai/chat` | body：`{ messages: [{role:'user'|'assistant', content}, ...] }`（含本次提问，前端维护最近 10 轮）；响应 **text/event-stream**，逐 token 输出；system 提示词含"美食专家"人设 |

> 多轮实现：**后端无状态**，把 history + 新提问一起发给百炼；回答直接 SSE 回传，前端逐字渲染（打字机效果）。后端负责拼 system prompt、截断超长历史、错误兜底为一条 SSE 错误事件。

## 7. 一对一聊天（登录，WebSocket）

| Method | Path | 说明 |
|---|---|---|
| WS | `/api/ws/chat?token=xxx` | 连接即建立 userId→session 映射；消息格式 `{type:'chat', toUserId, content}`；服务端落库后推送 `{type:'chat', message:{...}}`；对方离线则仅落库，上线后拉取 |
| GET | `/api/chat/conversations` | 会话列表：按对方聚合最近一条消息 + 未读数 |
| GET | `/api/chat/history` | 与某人的历史：`peerId, page, size`（倒序分页） |
| GET | `/api/chat/unread-count` | 总未读数（导航栏红点，前端定时轮询 / WS 事件后刷新） |
| POST | `/api/chat/read` | 标记已读：body `peerId`（打开某人会话时调用，将该方向 is_read 置 1） |

## 9. 我的内容管理（登录，归属强校验：只能操作自己的数据）

| Method | Path | 说明 |
|---|---|---|
| POST | `/api/my/recipe` | 发布菜谱：主表 + ingredients[] + steps[] **同事务**写入，status=0 |
| PUT | `/api/my/recipe/{id}` | 编辑（主从全量替换），status 重置 0、清 reject_reason |
| DELETE | `/api/my/recipe/{id}` | 删除（Service 层先删 ingredient/step/like/favorite/comment 再删主表） |
| GET | `/api/my/recipe` | 我的菜谱分页，参数 `status?`（0/1/2 筛选，展示审核状态与拒绝理由） |
| GET | `/api/my/favorites` | 我的收藏分页（JOIN 菜谱，仅显示仍存在的菜谱） |
| GET | `/api/my/comments` | 我的评论分页（JOIN 菜谱标题，便于跳转） |
| POST | `/api/my/store-visit` | 发布探店信息，status=0 |
| PUT | `/api/my/store-visit/{id}` | 编辑，重置待审核 |
| DELETE | `/api/my/store-visit/{id}` | 删除（级联删预约无引用，探店删除不影响历史预约） |
| GET | `/api/my/store-visit` | 我的探店分页，`status?` 筛选 |

## 10. 管理端

> 除登录外全部要求 role=管理员；管理端复用 `POST /api/auth/login` 后按 role 进入，不单独做登录接口。

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/admin/dashboard` | 看板聚合接口（一次返回四项）：
  ① recipeCount/commentCount/storeVisitCount/reservationCount
  ② weekly 近 7 天每日发布数（**服务端补零，日期=今天往前推 7 天动态生成**）
  ③ categoryDist 各分类菜谱数（供饼图） |
| GET | `/api/admin/category/page` | 分类分页（keyword?） |
| POST | `/api/admin/category` | 新增分类（name 唯一校验） |
| PUT | `/api/admin/category/{id}` | 修改分类 |
| DELETE | `/api/admin/category/{id}` | 删除分类（**被菜谱引用时拒绝**并提示） |
| GET | `/api/admin/recipe/page` | 菜谱分页：`keyword?, categoryId?, status?` |
| GET | `/api/admin/recipe/{id}` | 菜谱完整预览：主表 + 食材 + 步骤 + 作者 |
| PUT | `/api/admin/recipe/{id}/audit` | 审核：body `{status: 1|2, reason?}`；**status=2 时 reason 必填**（后端校验） |
| DELETE | `/api/admin/recipe/{id}` | 删除菜谱（含从表/互动数据） |
| GET | `/api/admin/comment/page` | 评论分页（keyword? 按内容/作者昵称） |
| DELETE | `/api/admin/comment/{id}` | 删除评论（递归清子孙） |
| GET | `/api/admin/store-visit/page` | 探店分页：`keyword?, status?` |
| PUT | `/api/admin/store-visit/{id}/audit` | 审核探店（规则同菜谱审核） |
| DELETE | `/api/admin/store-visit/{id}` | 删除探店 |
| GET | `/api/admin/reservation/page` | 预约分页（keyword?，按店铺名/手机号）——只读维护 |
| DELETE | `/api/admin/reservation/{id}` | 删除预约记录 |
| GET | `/api/admin/banner/page` | 轮播分页 |
| POST | `/api/admin/banner` | 新增：body `{recipeId, image, sort}`（**校验 recipeId 对应菜谱 status=1**） |
| PUT | `/api/admin/banner/{id}` | 修改 |
| DELETE | `/api/admin/banner/{id}` | 删除 |
| GET | `/api/admin/notice/page` | 公告分页 |
| POST | `/api/admin/notice` | 新增公告 |
| PUT | `/api/admin/notice/{id}` | 修改公告 |
| DELETE | `/api/admin/notice/{id}` | 删除公告 |
| GET | `/api/admin/admins/page` | 管理员分页（role=1） |
| POST | `/api/admin/admins` | 新增管理员：body `{username, password, nickname}`（username 唯一；同账号不能既是用户又是管理员） |
| PUT | `/api/admin/admins/{id}` | 编辑管理员（昵称/重置密码） |
| DELETE | `/api/admin/admins/{id}` | 删除管理员（**禁止删除自己**） |
| GET | `/api/admin/users/page` | 用户分页（role=0，keyword?） |
| POST | `/api/admin/users` | 新增用户（默认密码，走注册同逻辑） |
| PUT | `/api/admin/users/{id}/expert` | 设置/取消达人：body `{expert: true|false}` |
| PUT | `/api/admin/users/{id}` | 编辑用户基本信息 |
| DELETE | `/api/admin/users/{id}` | 删除用户（**存在发布内容/评论/预约等引用时拒绝**并提示） |
| GET | `/api/admin/profile` | 当前管理员信息 |
| PUT | `/api/admin/profile/password` | 管理员改密 |

> 管理员端是否显示"审核中的内容"的完整内容预览：菜谱审核走 `GET /api/admin/recipe/{id}` 预览（含食材/步骤），探店审核在列表弹窗内看全文——审核操作与预览同页完成，不额外做单独审核页。

## 11. 接口数量统计

| 模块 | 接口数 | 说明 |
|---|---|---|
| 账号 / 个人中心 | 5 | 注册登录 + 资料 + 改密 |
| 首页 / 分类 | 5 | 轮播、热门 x2、公告、分类 |
| 菜谱 | 8 | 列表 / 详情 / 点赞 x2 / 收藏 x2 / 我的管理 CRUD(4) 计入我的模块 |
| 评论 | 3 | 列表 / 发 / 删 |
| 探店 / 达人 / 预约 | 10 | 列表详情 / 达人榜 / 主页 x3 / 预约 4 |
| AI 专家 | 1 | SSE 流式 |
| 聊天 | 5 | WS + 会话 + 历史 + 未读 + 已读 |
| 我的内容 | 12 | 菜谱 4 + 收藏 1 + 评论 1 + 探店 4 + 预约 2 |
| 管理端 | 28 | 见 §10 |
| 上传 | 1 | 共用 |
| **合计** | **≈ 78** | 覆盖规格书全部功能点 |
