# 美食社区 · 开发排期（里程碑式，每阶段可运行可验收）

> 节奏原则：**每个里程碑结束时系统都能跑、能演示**，不做"最后一刻大联调"。
> 前端页面落地前用 hallmark 定 design tokens（用户端一套美食感主题、管理端同一体系不同布局），页面开发中按 ponytail 只做够用的实现。

## M0 · 地基与账号闭环（后端可跑通登录注册）

**产出**
- 目录骨架 + Git 初始化；`.env` 模板（MySQL 连接、JWT 密钥、百炼 API Key、上传目录）
- 后端：Spring Boot 3.5 工程（包名 `com.foodcommunity`），引入 MyBatis / PageHelper / Hutool / java-jwt / SpringAI-dashscope / WebSocket / Validation
- `common`：Result、全局异常、JWT 工具、两个拦截器（登录校验 + admin 角色校验）
- 启动初始化：无管理员时按配置自动创建 admin（**种子账号不进 SQL**，凭据走 .env）
- `sql/01_schema.sql` 建库
- 前端：Vite + Vue3 工程，路由双布局（用户端 Layout / 管理端 Layout），axios 封装 + token 注入 + 401 跳登录，Pinia 存用户信息
- 页面：登录 / 注册 / 个人中心（改资料、改密）

**验收**
1. 注册 → 登录 → 按 role 分别进入用户端/管理端
2. 未带 token 访问写接口返回 401；普通用户访问 `/api/admin/*` 返回 403
3. 启动即自动生成管理员账号，可用它登录管理端

## M1 · 内容主链：分类 + 菜谱（核心业务跑通）

**后端**
- 分类 CRUD（admin）+ 前台分类列表
- 菜谱发布/编辑/删除/我的列表（主从表同事务：ingredients + steps 全量替换）
- 审核接口（通过/拒绝必填理由）、管理端分页/详情预览
- 前台列表（分类/关键词筛选，仅已通过）、详情（views 自增、作者信息）
- 图片上传 + 静态映射
- 热门菜谱接口

**前端（用户端页面进 hallmark 设计流程，定首批 tokens）**
- 菜谱列表页（分类筛选栏）/ 菜谱详情页（Markdown 渲染：markdown-it）
- 发布/编辑菜谱表单（食材清单动态行 + 步骤动态行，封面上传）
- 我的菜谱（状态标签 + 拒绝理由展示）
- 管理端：分类管理页、菜谱管理页（含详情预览弹窗 + 审核操作条）

**验收**
1. 用户发菜谱 → 管理端审核通过 → 前台可见；拒绝则用户看到理由、修改后回到"待审核"
2. 编辑已通过菜谱后状态自动变待审核

## M2 · 社区互动：评论 / 收藏 / 点赞 / 作者主页 / 轮播

**后端**
- 评论：发评（楼中楼 parentId/rootId/replyUserId）、根评论分页（带子评论）、递归删除（我的 + 管理端共用同一 service）
- 收藏/点赞：toggle + 唯一键幂等 + likes_count 冗余维护；详情页回传 isLiked/isFavorited
- 作者主页：profile + 已通过菜谱/探店分页
- 轮播 CRUD（admin，关联菜谱必须已通过）+ 前台 banner 列表
- 我的收藏 / 我的评论

**前端**
- 菜谱详情页补：收藏/点赞按钮、楼中楼评论组件（回复 @、展开收起）、作者卡片 → 作者主页
- 作者主页页（复用达人主页同组件）
- 我的收藏 / 我的评论页
- 管理端：评论管理页、轮播图管理页（选菜谱弹窗只列已通过菜谱）
- 首页接入轮播 + 热门菜谱

**验收**
1. A 发根评论 → B 回复 A → 展示"回复 @A"；删根评论，其下子孙全部消失
2. 取消收藏按钮实时生效；重复点赞不产生重复记录

## M3 · 探店链路：探店 + 达人榜 + 预约双主体

**后端**
- 探店发布/编辑/删除/我的列表（复用 recipe 审核 service 模式，抽公共审核逻辑）
- 前台探店列表/详情（views 自增）
- 达人榜（heat = SUM(通过探店 views)*2 降序）
- 预约：发起（校验对方是达人）、双视角列表（direction=initiated|received）、达人同意/拒绝（拒绝必填理由）；管理端只读列表 + 删除

**前端**
- 探店列表页（详情弹窗）/ 我的探店 / 发布编辑探店
- 达人榜页 → 达人主页（预约按钮 + 私聊按钮）
- 预约弹窗表单（店铺名称/介绍/地址/电话/备注）
- 我的预约页（我发起 / 我接收 两个 tab；接收 tab 有同意/拒绝操作）
- 管理端：探店管理（含审核）、预约管理

**验收**
1. 非达人不进达人榜；达人主页热度 = 其探店浏览量合计 × 2 且只算已通过
2. 用户预约达人 → 达人"我接收的"看到 → 拒绝填理由后用户端可见理由

## M4 · 创新点一：AI 美食专家（百炼 + SSE 流式）

**后端**
- SpringAI + DashScope 配置（api-key/model 全走 .env，不硬编码）
- `/api/ai/chat`：接收 messages 历史（最近 10 轮）→ 拼 system 人设 → 流式响应 SSE
- 错误兜底：异常时输出一条 SSE error 事件而非断流

**前端**
- AI 助手页：聊天气泡 UI（markdown 渲染）、**逐字流式渲染**、多轮追问、加载态、清空会话
- （此页 hallmark：给聊天产品感，不做模板化左列表右窗口的堆砌）

**验收**
1. 问"红烧肉怎么去腥"能流式逐字回答；追问"那收汁要注意什么"能结合上文
2. 断网/超时给出错误气泡，页面不白屏不卡死

## M5 · 创新点二：WebSocket 一对一聊天 + 未读红点 + 公告

**后端**
- WS 端点 `/api/ws/chat`：握手 token 校验、userId→session 注册表、发送落库 → 在线推送 / 离线仅落库
- 会话列表（按对方聚合 + 未读数）、历史分页、标记已读
- 公告 CRUD（admin）+ 前台列表/详情 + 首页最新公告

**前端**
- 聊天列表页（会话 + 未读红点）/ 聊天窗口页（滚动加载历史、发送即更新、WS 实时收）
- 导航栏总未读数红点（WS 事件 + 轮询双保险）
- 达人页"私聊"按钮直达聊天窗口
- 公告列表/详情 + 首页公告条
- 管理端：公告管理页

**验收**
1. 双开两账号 A、B：A 发 B 立刻收到无需刷新；B 关页面时 A 发，B 回来红点 + 历史可见
2. 打开会话后未读清零；删管理员公告用户端即刻消失

## M6 · 管理端看板 + 全量收尾

**后端**
- `/api/admin/dashboard` 聚合：四项计数 + 近 7 天每日发布（**服务端补零，今天往前推 7 天动态生成**）+ 分类分布
- 管理员管理（增删改查 + 禁删自己）、用户管理（增删改查 + 设/取消达人、删除保护）

**前端**
- 管理端首页看板：四张统计卡 + ECharts 折线图 + 饼状图（空数据态处理）
- 管理员管理页 / 用户管理页
- 全量回归：权限边界、空态文案、错误提示、加载骨架

**验收**
1. 造数据 → 折线图正好 7 个点、含 0 值日期；饼图分类比例正确
2. 管理员列表不能删自己；删除有内容用户被拒绝并提示原因

## 开发顺序依赖图（一句话版）

```
M0 地基 ─▶ M1 菜谱审核主链 ─▶ M2 互动评论 ─▶ M3 探店预约
                                  │
M0 ──────────────────────────────┴─▶ M4 AI 专家（独立，可并行）
M0 ──────────────────────────────┴─▶ M5 WebSocket 聊天（独立，可并行）
M1~M5 全部 ─▶ M6 看板收尾
```

**建议做法**：按 M0→M6 顺序推进，每完成一个里程碑跑一遍验收清单再进下一个。M4 和 M5 与前序里程碑耦合低，卡壳时可并行穿插。
