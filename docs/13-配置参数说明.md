## 2. 环境变量配置（`backend/.env`）

### 2.1 创建方式

```bash
cp backend/.env.example backend/.env
# 然后按本机实际情况修改
```

`.env` 已被 `gitignore`（根目录与 backend 各有一份规则兜底），**不会提交到仓库**。

### 2.2 参数完整清单

| 变量名 | 必填 | 默认值 | 说明 |
|---|:---:|---|---|
| `MYSQL_HOST` | ✅ | `localhost` | 数据库主机 |
| `MYSQL_PORT` | ✅ | `3306` | 数据库端口 |
| `MYSQL_DATABASE` | ✅ | `food_community` | 数据库名（连接串带 `createDatabaseIfNotExist=true`，库不存在会自动建） |
| `MYSQL_USERNAME` | ✅ | `root` | 数据库账号 |
| `MYSQL_PASSWORD` | ✅ | 空 | 数据库密码 |
| `JWT_SECRET` | ✅ | — | **必须 ≥ 32 字符**，否则后端启动直接失败 |
| `ADMIN_USERNAME` | 推荐 | `admin` | 首次启动自动创建的管理员账号（库中无管理员时生效） |
| `ADMIN_PASSWORD` | 推荐 | `admin123` | 管理员密码（BCrypt 加密后入库） |
| `ALIYUN_MAAS_API_KEY` | 可选 | 空 | 阿里云百炼 API Key；**留空时后端照常启动**，仅 AI 接口返回提示 |
| `DASHSCOPE_API_KEY` | 可选 | 空 | 上者的备用变量名（`ALIYUN_MAAS_API_KEY` 优先级更高） |
| `AI_MODEL` | 可选 | `qwen-plus` | AI 模型名 |
| `AI_BASE_URL` | 可选 | 百炼 compatible-mode 地址 | AI 服务地址，**不要带 `/v1`**（Spring AI 会自动拼 `/v1/chat/completions`） |

### 2.3 推荐配置（本机实测可用）

```ini
# ---- MySQL 连接 ----
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_DATABASE=food_community
MYSQL_USERNAME=root
MYSQL_PASSWORD=123456

# ---- JWT 签名密钥（必须 ≥ 32 字符）----
JWT_SECRET=dev-only-secret-please-change-0123456789abcdef

# ---- 管理员自动初始化 ----
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123

# ---- AI 美食专家（可留空）----
ALIYUN_MAAS_API_KEY=
AI_MODEL=qwen-plus
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode
```

### 2.4 `.env` 加载机制（重要）

`EnvLoader` 是一个约 30 行的自研加载器（不引入 dotenv 依赖），规则：

1. 依次探测 **`./backend/.env`** 与 **`../.env`**（同时覆盖 IDEA 与命令行两种启动目录）；
2. 只解析 `KEY=VALUE` 行，跳过空行与 `#` 注释；
3. **仅当系统环境变量与系统属性都不存在该 key 时才注入** —— 即优先级为：
   **系统环境变量 > 启动参数 > `.env`**；
4. 必须在 `SpringApplication.run()` 之前调用，否则 `application.yml` 的占位符解析不到。

> ⚠️ **踩坑提示**：由于规则 3，若操作系统里已存在同名变量（如宿主环境注入的
> `SERVER__PORT`），`.env` 中的同名配置**不会生效**。排查配置不生效时优先检查系统环境变量。

### 3.2 数据库连接串

```
jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DATABASE:food_community}
  ?useUnicode=true
  &characterEncoding=utf8
  &useSSL=false
  &serverTimezone=Asia/Shanghai
  &allowPublicKeyRetrieval=true
  &createDatabaseIfNotExist=true
```

| 参数 | 作用 |
|---|---|
| `characterEncoding=utf8` | 中文不乱码（配合库的 utf8mb4） |
| `serverTimezone=Asia/Shanghai` | 修正时区偏移，避免时间差 8 小时 |
| `allowPublicKeyRetrieval=true` | MySQL 8 默认 caching_sha2_password 认证必需的放行项 |
| `createDatabaseIfNotExist=true` | 库不存在自动创建（表结构仍需手动执行 SQL） |

## 4. 端口配置

### 4.1 端口清单

| 服务 | 默认端口 | 说明 |
|---|---|---|
| 后端 API | **8080**（由 `backend/.env` 的 `SERVER_PORT` 控制） | `application.yml` 的 `server.port` |
| 前端 Vite | **5173** | `vite.config.js` 的 `server.port` |
| WebSocket | 与后端同端口 | 路径 `/api/ws/chat` |
| MySQL | **3306** | 数据库 |

### 4.2 端口被占用时（重要）

**现象**：启动报 `Web server failed to start. Port XXXX was already in use.`

**根因**：端口被其他程序占用（本机很常见，比如同时跑着别的 SpringBoot 项目）。

**✅ 推荐做法：只改 `backend/.env` 一处**

```ini
# backend/.env
SERVER_PORT=8081
```

改完重启后端即可。**前端代理、全部验收脚本都会自动读取同一份配置**，
不需要传 `BACKEND_PORT`，也不需要加 `--server.port` 参数。

> 该能力由 `application.yml` 的 `port: ${SERVER_PORT:8080}` +
> 自研 `EnvLoader`（启动时把 `.env` 注入系统属性）共同实现。
>
> 实现要点：`server.port` 曾是全项目**唯一硬编码**的配置项（其他如数据库、
> JWT、AI 全都走 `${ENV:default}`），导致换端口必须手工传参、且各脚本默认值
> 与真实端口脱节。现已统一。

**⚠️ 警惕环境变量劫持**：Spring Boot 的 relaxed binding 会把环境变量
`SERVER_PORT`（或 `SERVER__PORT`）自动映射为 `server.port`，**优先级高于 `application.yml`**。
若宿主环境（如某些 IDE / 工具链）注入了该变量，`.env` 里的配置会被悄悄覆盖。

```bash
# 查看是否被环境变量劫持
env | grep -i "server_port\|server__port"

# 查看端口占用（Windows）
netstat -ano | grep ":8080"
```

**临时覆盖**（不改 `.env`，适合一次性调试）：

```bash
# 后端：清掉可能劫持的变量，再显式指定端口
unset SERVER__PORT
java -jar target/food-community-backend-0.0.1-SNAPSHOT.jar --server.port=8082

# 前端 / 验收脚本：临时覆盖
BACKEND_PORT=8082 npm run dev
BACKEND_PORT=8082 bash scripts/verify-m1.sh
BACKEND_PORT=8082 python scripts/verify-audit.py
```

> 端口解析优先级：**环境变量 `BACKEND_PORT` > `backend/.env` 的 `SERVER_PORT` > 8080**。

## 5. AI 服务配置

### 5.1 接入方式

通过 **OpenAI 兼容端点**接入阿里云百炼（DashScope），使用 Spring AI 官方适配器。

| 项 | 值 |
|---|---|
| 提供商 | 阿里云百炼（DashScope） |
| Base URL | `https://dashscope.aliyuncs.com/compatible-mode` |
| 默认模型 | `qwen-plus` |
| 协议 | SSE (`text/event-stream`) 流式 |

### 5.2 获取 API Key

1. 访问阿里云百炼控制台 <https://bailian.console.aliyun.com/>
2. 进入「API-KEY 管理」创建 Key
3. 将 Key 写入 `backend/.env` 的 `ALIYUN_MAAS_API_KEY=`（也可写系统环境变量，优先级更高）
4. 重启后端

### 5.3 降级行为（未配置 Key 时）

| 场景 | 表现 |
|---|---|
| 后端启动 | ✅ **正常启动**，不受影响 |
| 其他所有接口 | ✅ 正常工作 |
| 调用 `/api/ai/chat` | ❌ 返回 `AI 服务尚未配置：请在 backend/.env 中设置 DASHSCOPE_API_KEY 后重启` |

> 这是刻意设计的**功能降级**而非整体不可用，便于在无 Key 环境下演示其他模块。

### 5.4 AI 运行时参数

| 参数 | 值 | 说明 |
|---|---|---|
| 历史轮数上限 | **10 条** | `AiChatService.MAX_HISTORY`，超出仅取最近 10 条，防超长 |
| 无状态多轮 | 是 | 后端不存会话，历史由前端携带 |
| 异常兜底 | 是 | 流中断返回 `⚠️ 回答中断：<原因>` 事件，不白屏 |

### 6.1 `vite.config.js`

| 配置项 | 值 | 说明 |
|---|---|---|
| `server.port` | `5173` | 开发服务器端口 |
| `server.proxy['/api'].target` | `http://localhost:${BACKEND_PORT \|\| .env 的 SERVER_PORT \|\| 8080}` | API 代理，**自动跟随 `backend/.env`** |
| `server.proxy['/api'].ws` | `true` | **开启 WebSocket 升级**（`/api/ws/chat` 必需） |

> 因为代理已处理跨域，**前端不需要配置 CORS**；后端 `WebConfig` 虽放行了
> `allowedOriginPatterns("*")`，但开发时请求实际走 Vite 代理，同源。

### 6.2 axios 封装（`src/api/request.js`）

| 参数 | 值 | 说明 |
|---|---|---|
| `baseURL` | `/api` | 统一前缀，配合 Vite 代理 |
| `timeout` | `30000`（30 秒） | 普通请求超时 |
| 请求拦截 | 自动加 `Authorization: Bearer <token>` | token 从 Pinia store 取 |
| 响应拦截 | `code===200` 放行；`401` 自动登出跳登录页；其他弹 `ElMessage.error` | 统一错误处理 |

### 6.3 登录态持久化

| 项 | 值 |
|---|---|
| 存储位置 | `localStorage` |
| token key | **`fc_token`** |
| 用户信息 key | `fc_user` |
| 行为 | 刷新页面登录态不丢失；登出时清除两个 key |

### 6.4 路由守卫（`src/router/index.js`）

| 规则 | 行为 |
|---|---|
| `meta.public === true`（如 `/login`） | 直接放行 |
| 未登录访问受保护页 | 重定向到 `/login`，并带 `redirect` 参数记录原目标 |
| `meta.adminOnly === true` 且非管理员 | 拦截（`/admin/**`） |
| 未匹配路由 | 重定向到 404 页面 |

## 7. 数据库初始化配置

### 7.1 执行顺序（必须按序）

```bash
mysql -uroot -p < sql/01_schema.sql          # ① 建库建表（13 张，必需）
mysql -uroot -p < sql/02_seed_demo.sql       # ② 分类 + 菜谱 + 演示作者
mysql -uroot -p < sql/03_seed_m3.sql         # ③ 探店 + 预约
mysql -uroot -p < sql/04_seed_m6.sql         # ④ 看板时间分布 + 楼中楼评论
mysql -uroot -p < sql/05_seed_supplement.sql # ⑤ 轮播 + 公告 + 点赞/收藏/聊天
```

| 脚本 | 必需 | 幂等 | 说明 |
|---|:---:|:---:|---|
| `01_schema.sql` | ✅ | ❌ | 重复执行报 `Table 'user' already exists`（预期行为，表已存在） |
| `02_seed_demo.sql` | 推荐 | ⚠️ 部分 | 用 `ON DUPLICATE KEY UPDATE`，但**重复执行会导致菜谱重复** |
| `03_seed_m3.sql` | 推荐 | ⚠️ 部分 | 预约记录会重复追加 |
| `04_seed_m6.sql` | 推荐 | ❌ | **重复执行会产生重复评论**（脚本注释已说明） |
| `05_seed_supplement.sql` | 推荐 | ✅ **幂等** | 全部 `WHERE NOT EXISTS` / `INSERT IGNORE`，可反复执行 |

> ⚠️ **重要**：`02`/`03`/`04` 三个脚本**不是幂等**的，重复执行会累积重复数据。
> 如需重置，请先清空相关表再重新导入，或直接重建库。

### 7.2 字符集要求

| 层级 | 要求 |
|---|---|
| 数据库 | `utf8mb4` / `utf8mb4_unicode_ci` |
| 表 | 继承库设置 |
| 连接 | `characterEncoding=utf8`（已在连接串中） |
| 命令行导入 | 建议加 `--default-character-set=utf8mb4` |

### 7.3 管理员账号说明

- **管理员种子不入 SQL**，由后端启动时的 `AdminInitializer` 按 `.env` 配置自动创建；
- 触发条件：**系统内无管理员时**才创建（已存在则跳过）；
- 创建失败**只告警不阻断启动**（避免刚建库时因配置问题整个应用起不来）。

## 9. 鉴权与安全配置

| 项 | 值 | 说明 |
|---|---|---|
| JWT 算法 | HMAC256 | `java-jwt` |
| 密钥要求 | **≥32 字符** | 不满足则 `JwtUtil` 构造时抛异常，**启动失败**（防弱密钥上线） |
| 有效期 | 24 小时 | `jwt.expire-hours` |
| 载荷 | `sub`=用户ID，`role`=角色 | — |
| 请求头 | `Authorization: Bearer <token>` | — |
| 密码存储 | BCrypt 加盐哈希 | Hutool `BCrypt`，不存明文 |
| 拦截范围 | `/api/**` | `AuthInterceptor` |

**白名单与拦截规则**

| 路径 | 规则 | 失败码 |
|---|---|---|
| `/api/auth/login`、`/api/auth/register` | 放行 | — |
| `/api/admin/**` | 需 JWT + `role=1` | 401 / 403 |
| `/api/my/**`、`/api/chat/**` | **GET 也需登录** | 401 |
| 其余非 admin 路径 | GET 放行；写操作需 JWT | 401 |
| `WS /api/ws/chat` | 握手校验 `?token=` | 握手拒绝 |

> **约定**：鉴权失败时 **HTTP 状态码恒为 200**，错误码放响应体 `code` 字段。
> 这是为了让前端能在 axios 响应拦截器里统一处理，不用区分网络层与业务层错误。

## 12. 常见问题排查

| 现象 | 可能原因 | 解决方案 |
|---|---|---|
| 启动报 `Port XXXX was already in use` | 端口被其他程序占用 | 改 `backend/.env` 的 `SERVER_PORT` 换端口即可（前端与脚本会自动跟随）；若怀疑被环境变量劫持，用 `env \| grep -i server_port` 排查 |
| 启动报「端口 X 上不是本项目后端」 | 脚本读到的端口与实际后端不一致 | 核对 `backend/.env` 的 `SERVER_PORT` 是否与后端启动日志一致，改完重启后端 |
| 启动报 `jwt.secret 未配置或长度不足 32 位` | `.env` 缺失或 `JWT_SECRET` 太短 | 在 `backend/.env` 设置 ≥32 字符的 `JWT_SECRET` |
| 启动打印「未找到 .env 文件」 | `.env` 不在 `./` 或 `../` 下 | 确认 `backend/.env` 存在；注意启动目录 |
| 数据库连不上 | 账密错、MySQL 未启动、端口不符 | 核对 `.env` 的 `MYSQL_*`；用 `mysql -uroot -p` 手动验证连通性 |
| 中文显示为乱码 / `Binary file matches` | 命令行编码问题 | 查询时加 `--default-character-set=utf8mb4 --batch --raw`；导入时同样指定 |
| 前端请求全部 404 | Vite 代理目标端口与后端不一致 | 确认 `backend/.env` 的 `SERVER_PORT` 正确后重启 `npm run dev`；`vite.config.js` 会自动读取该值 |
| WebSocket 连接失败 | 代理未开 `ws: true`，或 token 未带 | 检查 `vite.config.js` 的 `ws: true`；确认连接串含 `?token=` |
| AI 接口返回「AI 服务尚未配置」 | 未设置 API Key | 在 `.env` 设置 `ALIYUN_MAAS_API_KEY` 后重启 |
| 上传图片 404 | 启动目录与 `upload.dir` 不一致 | 统一从 `backend/` 目录启动；或改用绝对路径 |
| 分页查询页码越界返回空 | — | `pagehelper.reasonable=true` 已自动矫正到边界，属预期行为 |
| 修改菜谱后前台看不到了 | — | 编辑会**重置为待审核**，属预期行为，需管理员重新审核 |
| `04_seed_m6.sql` 重复执行产生重复评论 | 脚本非幂等 | 只执行一次；或先清理 `comment` 表再导入 |

## 13. 生产部署注意事项

> 本项目为毕设演示项目，以下为若要上线需改造的点。

| 项 | 当前（开发） | 生产建议 |
|---|---|---|
| 数据库凭据 | `.env` 明文 | 使用密钥管理服务 / 环境变量注入 |
| JWT 密钥 | 示例值 | 生成强随机密钥并定期轮换 |
| CORS | `allowedOriginPatterns("*")` | 收敛为具体域名白名单 |
| 上传存储 | 本地磁盘 | 迁移至对象存储（已抽象 `FileStorageService`，替换实现即可） |
| 图片访问 | 静态目录直出 | 走 CDN + 防盗链 |
| 日志 | `info` 级别 | 接入集中式日志，敏感字段脱敏 |
| 前端 | Vite dev server | `npm run build` 后由 Nginx 托管静态资源并反代 `/api` |
| 数据库连接池 | Hikari 默认 | 按并发量调整 `maximum-pool-size` |
