## 后端新增

| 模块 | 实现要点 |
|---|---|
| WebSocket | `spring-boot-starter-websocket`；端点 `/api/ws/chat?token=xxx`；**握手拦截器 JWT 校验**（无效直接拒绝连接）；`WsSessionRegistry`（ConcurrentHashMap userId→session，同人多端后连覆盖） |
| 消息链路 | 入站 `{toUserId,content}` → **落库 chat_message** → 对方在线则实时推送 `{type:'chat',message}`；离线仅落库（会话拉取 + 未读补偿） |
| 会话聚合 | 一条 SQL "每组取最大 id" 得最近消息；未读按对方分组 `COUNT(is_read=0)`；JOIN 双方昵称头像；`/api/chat/conversations` |
| 历史/未读 | `/api/chat/history?peerId&page`（倒序分页）、`unread-count`、`/read`（标记某方向已读） |
| 权限 | `/api/chat/**` 纳入拦截器"必登录"（私人 GET） |
| 公告 | Notice 实体/Mapper/Service：前台分页/最新/详情 + 管理端增删改查（keyword）；无上下线开关，删除即下线 |

## 前端新增

- 会话列表页 `/chat`：最近消息 + 时间 + **未读角标**，自动 20s 轮询刷新总未读
- 聊天窗口页 `/chat/:peerId`：历史分页（加载更早）、**WebSocket 实时收发**（断线 3s 自动重连）、Enter 发送、标记已读、对方头像/昵称（无会话时从作者主页补）
- 达人主页「💬 私聊」按钮启用 → 直达聊天窗口
- 导航头像下拉：聊天（**el-badge 未读红点**）+ 系统公告
- 公告：首页顶部公告条（点击进公告页）、公告列表/详情弹窗页 `/notices`
- 管理端：公告管理（增删改查 + 预览 + Markdown）
- Vite 代理开启 `ws:true` 支持 WebSocket 升级

## 实测（沙箱，真机双账号）

**WebSocket 冒烟 8/8 通过**（`node scripts/smoke-ws.mjs`）：

| 项 | 结果 |
|---|---|
| A/B 注册登录 | ✅ |
| A/B WS 握手（JWT 校验） | ✅ |
| B 实时收到 A 消息（无刷新） | ✅ |
| B 未读数 = 1 | ✅ |
| A 实时收到 B 回复 | ✅ |
| B 标记已读后未读 = 0 | ✅ |
| A 会话列表最近消息正确 | ✅ |
| A↔B 历史共 2 条 | ✅ |

公告公开链路（列表/latest/详情 空态 + 404 提示）+ 匿名聊天 401 ✅；前端构建 ✅ 1.4s。

> 公告 CRUD 闭环脚本：`bash scripts/verify-m5.sh`；WebSocket 随时可重跑 `node scripts/smoke-ws.mjs`。

## 浏览器体验

1. 双开两个浏览器（普通窗口 + 无痕）分别登录 A/B → A 头像下拉「聊天」→ 找到 B 进入窗口 → 互发消息，另一窗口**无需刷新**实时收到
2. 关掉 B 窗口让 A 发消息 → B 回来导航栏出现**红色未读数**
3. 达人主页点「私聊」直达
4. admin 发公告 → 用户端首页顶部公告条与 `/notices` 立即可见
