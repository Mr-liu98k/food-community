## 后端新增

| 模块 | 实现要点 |
|---|---|
| 探店信息 | StoreVisit 实体/Mapper/Service：与菜谱相同的审核状态机（0/1/2 + 拒绝必填理由）、编辑重置待审、浏览量自增、我的 CRUD、前台仅放行已通过 |
| 达人榜 | `/api/expert/list`：`is_expert=1` 用户，SQL 聚合 `heat = SUM(通过探店 views) * 2`，LEFT JOIN 保证无探店达人也上榜，降序 |
| 探店预约 | Reservation：**双主体**（initiator_id 发起 / expert_id 被预约达人）+ 状态机 0待处理/1同意/2拒绝；`direction=initiated|received` 双视角；**同意/拒绝仅被预约达人**（service 校验 expert_id=当前用户），拒绝理由必填；校验对方确实是达人、不能预约自己 |
| 作者主页 | `AuthorProfile` 增加 storeVisitCount；`/api/user/{id}/store-visits` 已通过分页 |
| 管理端 | 探店信息审核（预览/通过/拒绝）、预约只读维护（搜索+删除） |
| 权限修复 | **拦截器补充 `/api/my/**` 必须登录**（此前游客 GET 会落到空列表而非 401），并回归验证 |

## 前端新增

- 探店列表页（卡片 + **详情弹窗**，打开即浏览量+1，Markdown 渲染）
- 探店达人榜页（名次 + 热度 = views×2，点击进主页）
- 我的探店（状态筛选/编辑/删除）+ 发布/编辑探店页
- 我的预约页（我发起 / 我接收 两个 tab，达人对待处理预约同意/拒绝，拒绝填理由）
- 作者主页升级：菜谱 / 探店 双 tab；达人头像区显示「📅 预约探店」按钮 + 预约表单弹窗
- 管理端：探店信息管理（审核）、探店预约管理
- 导航（探店/探店达人）、下拉菜单（我的探店/探店预约）、管理端菜单同步

## 浏览器体验路径

1. 首页/导航 → 探店 → 点卡片看弹窗详情
2. 探店达人 → 达人榜（热度 1068）→ 进「厨艺小当家」主页 → **预约探店**填表提交
3. admin → 探店预约信息 → 查看两条演示预约（含状态）
4. 用你注册的账号发布探店 → admin 审核通过 → 前台可见；达人（需 admin 把你设为达人，M6 提供界面，暂可手动 SQL/脚本）
