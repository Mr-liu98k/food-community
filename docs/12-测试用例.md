## 0. 测试说明

### 0.1 测试策略

| 层级 | 手段 | 覆盖范围 |
|---|---|---|
| 接口测试 | `curl` + 里程碑验收脚本 | 全部 REST 接口主流程与异常分支 |
| 集成测试 | `scripts/verify-m*.sh` | 跨模块业务闭环（发布→审核→可见） |
| 实时通信测试 | `scripts/smoke-ws.mjs`（Node 22 内置 WebSocket） | WebSocket 双端收发 |
| AI 链路测试 | `scripts/smoke-ai.sh` | SSE 流式输出 |
| 权限测试 | 无 token / 普通用户 / 管理员 三种身份交叉验证 | 越权防护 |
| **内容审核自动化** | **`scripts/verify-audit.py`（Python 标准库，零依赖）** | **菜谱+探店双线审核状态机全链路 58 项** |

> **回归入口**：改动审核相关代码后，执行 `python scripts/verify-audit.py`
> （后端非 8080 时加 `BACKEND_PORT=8081`；Windows 可双击 `scripts\verify-audit.bat`）。
> 约 0.7 秒跑完 58 项断言，全部通过则自动清理测试数据，失败则保留现场。

### 0.2 环境准备

```bash
# 1) 建库 + 导入演示数据
mysql -uroot -p < sql/01_schema.sql
mysql -uroot -p < sql/02_seed_demo.sql
mysql -uroot -p < sql/03_seed_m3.sql
mysql -uroot -p < sql/04_seed_m6.sql
mysql -uroot -p < sql/05_seed_supplement.sql

# 2) 配置并启动后端（注意本机若 8080 被占用需换端口）
cp backend/.env.example backend/.env && vi backend/.env
cd backend && mvn clean package -DskipTests
java -jar target/food-community-backend-0.0.1-SNAPSHOT.jar --server.port=8081

# 3) 启动前端
cd frontend && npm install && BACKEND_PORT=8081 npm run dev
```

### 13.3 注意事项

1. **验收脚本会写入测试数据**（随机账号、测试分类、测试菜谱），跑完自动清理；
   但 `verify-m0/m6` 会留下少量用户，建议回归后清理：
   ```sql
   DELETE FROM user WHERE username LIKE 'm0user_%' OR username LIKE 'm1_%'
      OR username LIKE 'm5_%' OR username LIKE 'm6u_%' OR username LIKE 'smoke_%';
   ```
2. **`04_seed_m6.sql` 会产生重复评论**，重复执行需注意；
   `05_seed_supplement.sql` 为幂等写法，可反复执行。

4. 数据库中文输出在 Windows 命令行可能显示为二进制转义，建议加 `--default-character-set=utf8mb4 --batch --raw` 参数。
5. **审核是「一次性」动作**：记录进入 `status=2`（已拒绝）后，**不能直接改判为通过**，
   会返回「不在待审核状态，请勿重复操作」。需用户编辑内容触发状态重置为 0 后，才能再次审核。
   写自动化用例时必须为「拒绝分支」与「通过分支」准备**两条独立记录**，否则会误判为缺陷。

### 13.4 审核链路的真实行为基线（`verify-audit.py` 实测确认）

以下文案与错误码均从后端源码与真实响应核对得出，是自动化断言的依据：

| 场景 | HTTP | 响应 code | 文案 |
|---|---|---|---|
| 待审菜谱前台详情 | 200 | 500 | 该菜谱不存在或尚未通过审核 |
| 待审探店前台详情 | 200 | 500 | 该探店信息不存在或尚未通过审核 |
| 拒绝不填理由 / 理由为空白 | 200 | 500 | 拒绝时必须填写拒绝理由 |
| 已通过/已拒后重复审核（菜谱） | 200 | 500 | 该菜谱不在待审核状态，请勿重复操作 |
| 已通过/已拒后重复审核（探店） | 200 | 500 | 该探店信息不在待审核状态，请勿重复操作 |
| `status=0` / `3` / 缺省 | 200 | **400** | 审核结果只能为通过(1)或拒绝(2) / 审核结果不能为空 |
| 审核不存在的 ID | 200 | 500 | 菜谱不存在 / 探店信息不存在 |
| 未登录调审核接口 | 200 | 401 | 未登录或登录已过期 |
| 普通用户调审核接口 | 200 | 403 | 无管理员权限 |
| 轮播关联未通过菜谱 | 200 | 500 | 只能关联【已审核通过】的菜谱 |

> **易错点**：`status=0/3` 由 Bean Validation（`AuditRequest` 的 `@Min(1) @Max(2)`）拦截，
> 返回 **code=400**；而「重复审核」「拒绝无理由」由 Service 层业务校验拦截，返回 **code=500**。
> 两者错误码不同，断言时不要混用。此外，鉴权失败时 **HTTP 状态码恒为 200**，错误信息只在响应体 `code` 字段。
